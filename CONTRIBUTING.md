# Contributing to grug

These guidelines are the same for every repository in the grug-lang organization. A repository can add rules of its own on top of them, such as grug-for-minecraft's `AGENTS.md`, but none contradicts them. A repository may also accept pull requests only from its members, and grug-for-minecraft does: its own `CONTRIBUTING.md` says so.

Create an issue before you make any pull request, as that gives everyone the chance to discuss it.

If you are planning to work on an issue, leave a comment asking to be assigned to the issue. Only work on issues that have the `planned` label.

High-quality, concise LLM-generated PRs are **only** welcome for issues labeled both `good first issue` and `planned`. They do not need to be assigned to you first, since these issues are written in enough detail to make the PRs easy to review. PRs that do not address all review feedback will be closed.

grug has an issue board that can be filtered to list [good first issues](https://github.com/orgs/grug-lang/projects/1/views/1?sliceBy%5Bvalue%5D=good+first+issue) and [planned issues](https://github.com/orgs/grug-lang/projects/1/views/1?sliceBy%5Bvalue%5D=planned). The [Next up](https://github.com/orgs/grug-lang/projects/2) board lists the issues that will be implemented next, in order, with the first one at the top.
